Unit Testing: 단위 테스트 전략과 모범 사례

Methodology Series Vol.2

단위 테스트(Unit Testing)는 소프트웨어의 가장 작은 테스트 가능한 부분을 독립적으로 검증하는 테스트 기법이다. 본 논문에서는 단위 테스트의 이론적 기반과 AAA(Arrange-Act-Assert) 패턴, FIRST 원칙 등 효과적인 테스트 작성을 위한 방법론을 분석한다. 또한 Mock, Stub, Spy 등 테스트 더블의 활용법과 주요 테스팅 프레임워크를 고찰한다. 체계적인 단위 테스트는 회귀 버그 방지, 리팩토링 안전성 확보, 설계 개선에 기여한다.
Keywords: Unit Testing, Test Double, Mock, AAA Pattern, FIRST Principles, Test Coverage

1. Introduction

단위 테스트는 1990년대 Kent Beck의 SUnit(Smalltalk)에서 체계화되어 JUnit(Java)을 거쳐 현대의 xUnit 프레임워크 계열로 발전했다. 단위 테스트의 "단위(Unit)"는 언어와 맥락에 따라 함수, 메서드, 클래스, 모듈 등으로 정의된다.

A test is not a unit test if it talks to the database, communicates across the network, touches the file system, or can't run at the same time as any of your other unit tests.

— Michael Feathers, Working Effectively with Legacy Code

2. Test Pyramid

테스트 피라미드는 단위 테스트를 가장 많이 작성하고, 통합 테스트는 적당히, E2E 테스트는 최소한으로 유지할 것을 권장한다. 이는 각 테스트 레벨의 속도, 비용, 안정성 특성에 기반한다.

3. AAA Pattern

1

Arrange (준비)

테스트에 필요한 객체 생성, 의존성 설정, 초기 상태 구성

2

Act (실행)

테스트 대상 메서드/함수를 호출하여 실제 동작 수행

3

Assert (검증)

기대 결과와 실제 결과를 비교하여 테스트 통과 여부 판정

4. FIRST Principles

Fast

테스트는 빠르게 실행되어야 함 (ms 단위)

Independent

테스트 간 의존성 없이 독립 실행 가능

Repeatable

환경에 관계없이 동일한 결과

Self-validating

성공/실패가 자동 판정

Timely

프로덕션 코드 작성 직전에 테스트 작성

5. Test Doubles

  • Mock: 기대되는 호출을 검증하는 객체. 행위(behavior) 검증에 사용
  • Stub: 미리 정의된 응답을 반환하는 객체. 상태(state) 테스트에 사용
  • Spy: 실제 객체를 감싸서 호출을 기록. 부분 Mock
  • Fake: 단순화된 동작 구현체. 예: 인메모리 DB
  • Dummy: 파라미터 채우기용 객체. 실제 사용되지 않음

6. Testing Frameworks

프레임워크 언어 특징
JUnit 5 Java 표준 테스팅 프레임워크, 어노테이션 기반
pytest Python 간결한 문법, fixture, 풍부한 플러그인
Jest JavaScript Zero config, 스냅샷 테스팅
xUnit .NET Fact/Theory 패턴, 모던 .NET 지원
RSpec Ruby BDD 스타일, 가독성 높은 DSL

7. Code Coverage

높은 코드 커버리지가 곧 좋은 테스트를 의미하지는 않는다. 80% 커버리지를 일반적인 목표로 삼되, 핵심 비즈니스 로직은 더 높은 커버리지를, 단순 getter/setter는 낮은 커버리지를 허용할 수 있다.

8. Anti-Patterns

  • The Liar: 항상 통과하지만 실제로 아무것도 검증하지 않는 테스트
  • The Giant: 너무 많은 것을 테스트하는 거대한 테스트
  • The Mockery: 과도한 Mocking으로 실제 동작과 괴리
  • The Slowpoke: 느린 테스트 (DB, 네트워크 호출 포함)
  • The Flickering: 간헐적으로 실패하는 불안정한 테스트

9. Benefits

조기 결함 발견

개발 중 버그를 즉시 발견하여 수정 비용 최소화

안전한 리팩토링

테스트 스위트가 변경에 대한 안전망 역할

실행 가능한 문서

테스트 코드가 사용법 예제 역할

설계 개선

테스트 용이성이 좋은 설계로 유도

배포 자신감

회귀 테스트로 배포 리스크 감소

디버깅 시간 단축

실패 테스트가 문제 위치를 정확히 지목

10. Conclusion

단위 테스트는 소프트웨어 품질 보증의 기초이자 TDD, 리팩토링, CI/CD의 필수 요소이다. FIRST 원칙을 준수하고 AAA 패턴을 활용한 체계적인 테스트 작성은 장기적으로 개발 생산성과 코드 품질을 크게 향상시킨다.
