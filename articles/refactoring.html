Refactoring: 코드 리팩토링의 원칙과 기법

Software Engineering Methodology Paper

Abstract

리팩토링은 외부 동작을 변경하지 않으면서 코드의 내부 구조를 개선하는 기법이다. Martin Fowler의 "Refactoring" 2판을 중심으로, 본 논문에서는 리팩토링의 정의와 목적, 주요 리팩토링 기법 카탈로그, 리팩토링을 안전하게 수행하기 위한 원칙을 분석한다. 테스트 주도 개발과 결합된 지속적인 리팩토링은 기술 부채를 관리하고 소프트웨어의 장기적인 건강을 유지하는 핵심 실천법이다.

Keywords: Refactoring, Code Smell, Technical Debt, Clean Code, Design Patterns, Software Maintenance

1. Introduction

리팩토링이라는 용어는 William Opdyke가 1992년 박사 논문에서 처음 사용했으며, Martin Fowler가 1999년 "Refactoring: Improving the Design of Existing Code"를 통해 널리 알렸다. 리팩토링은 "기능은 그대로, 구조만 개선"이라는 원칙 하에 코드의 가독성, 유지보수성, 확장성을 향상시킨다.

"Refactoring is a disciplined technique for restructuring an existing body of code, altering its internal structure without changing its external behavior."

— Martin Fowler

2. When to Refactor

🔁 Rule of Three

비슷한 코드를 세 번째 작성할 때 리팩토링하라. 세 번이면 패턴이다

➕ 기능 추가 시

새 기능을 추가하기 전에 기존 코드를 이해하기 쉽게 정리

🐛 버그 수정 시

버그를 찾기 어려웠다면, 그 코드는 리팩토링이 필요하다는 신호

👁️ 코드 리뷰 시

리뷰 중 발견된 코드 스멜을 즉시 개선

👃 코드 스멜 발견 시

중복, 긴 메서드, 큰 클래스 등의 스멜을 감지했을 때

🧹 보이스카웃 규칙

코드를 떠날 때 왔을 때보다 깨끗하게

3. Key Refactoring Techniques

📤 Extract Function

코드 조각을 별도의 함수로 추출. 가장 흔히 사용되는 리팩토링

코드 블록 → function calculateTotal()

📥 Inline Function

함수 본문이 함수 이름만큼 명확할 때, 호출부에 직접 삽입

isActive() { return age > 0; } → age > 0

✏️ Rename Variable/Function

이름을 더 명확하게 변경. 이해하기 쉬운 코드의 시작

d → elapsedDays, fn → calculateTax

📦 Extract Class

클래스가 너무 많은 책임을 가질 때 일부를 새 클래스로 분리

Person → Person + TelephoneNumber

🔀 Move Function

함수를 더 적절한 클래스로 이동. Feature Envy 해결

A.calculateFor(b) → B.calculate()

🔄 Replace Temp with Query

임시 변수를 메서드 호출로 대체

let total = base * tax → getTotal()

4. Refactoring Example

📝 Extract Function 예시
// Before function printBill(invoice) { let outstanding = 0; // calculate outstanding for (const o of invoice.orders) { outstanding += o.amount; } // print details console.log(`name: ${invoice.customer}`); console.log(`amount: ${outstanding}`); }
→
// After function printBill(invoice) { const outstanding = calculateOutstanding(invoice); printDetails(invoice, outstanding); } function calculateOutstanding(invoice) { return invoice.orders .reduce((sum, o) => sum + o.amount, 0); } function printDetails(invoice, outstanding) { console.log(`name: ${invoice.customer}`); console.log(`amount: ${outstanding}`); }

5. Refactoring Catalog

카테고리 리팩토링 기법 목적
기본 Extract/Inline Function, Rename 가독성, 명확성 향상
캡슐화 Encapsulate Variable/Collection 데이터 접근 제어
이동 Move Function/Field, Extract Class 책임 분리, 응집도 향상
조건부 Decompose/Consolidate Conditional 조건문 단순화
API Separate Query from Modifier 부수효과 제거
상속 Pull Up/Push Down Method 상속 구조 정리

6. Safe Refactoring

✅ 안전한 리팩토링을 위한 규칙

  1. 테스트 먼저: 리팩토링 전에 충분한 테스트 커버리지 확보
  2. 작은 단계: 한 번에 하나의 변경만. 각 단계 후 테스트 실행
  3. 자주 커밋: 작은 변경마다 커밋하여 롤백 가능하게
  4. 동작 유지: 외부 동작이 변경되면 리팩토링이 아님
  5. IDE 도구 활용: 자동화된 리팩토링 기능 사용
  6. 코드 리뷰: 리팩토링도 리뷰 대상

⚠️ 리팩토링하지 말아야 할 때

  • 테스트가 없고 추가할 수 없는 경우
  • 마감이 임박한 경우 (기술 부채로 기록)
  • 코드를 완전히 재작성하는 것이 나은 경우
  • 리팩토링과 기능 변경을 동시에 하려는 경우

7. Benefits

📖 가독성 향상

의도가 명확한 코드로 이해 시간 단축

🐛 버그 발견

코드를 정리하면서 숨겨진 버그 발견

⚡ 개발 속도

깨끗한 코드베이스에서 기능 추가가 더 빠름

🏗️ 설계 개선

점진적인 설계 개선으로 아키텍처 향상

💳 기술 부채 감소

지속적인 리팩토링으로 부채 축적 방지

📚 지식 공유

명확한 코드가 팀 전체의 이해도 향상

8. Conclusion

리팩토링은 소프트웨어의 장기적인 건강을 유지하는 핵심 실천법이다. "작동하는 코드"에서 "깨끗하게 작동하는 코드"로의 전환은 테스트와 함께 작은 단계로 진행되어야 한다.

효과적인 리팩토링을 위해서는 코드 스멜을 인식하는 능력, 적절한 리팩토링 기법을 선택하는 판단력, 그리고 테스트를 통한 안전망이 필요하다. 지속적인 리팩토링 문화는 기술 부채를 관리하고 소프트웨어의 수명을 연장하며, 개발팀의 생산성을 장기적으로 유지하는 기반이 된다.
